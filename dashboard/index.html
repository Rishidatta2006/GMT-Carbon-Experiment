D. Sustainability Engineering Analysis

1. Energy Disparity & Proportionality

The HIGH workload consumed significantly more total energy than the LOW workload over the identical 30-second measurement window. This demonstrates that computational intensity directly drives dynamic energy draw via CPU frequency scaling (P-states) and instruction retire rates.

2. The Idle Power Baseline

Crucially, the LOW workload did not consume zero energy. Even under minimal activity (~9% CPU load), the system consumed an estimated ~41 Joules. This illustrates static power dissipation: transistor leakage current, motherboards, DRAM refresh cycles, and OS scheduler overhead persist regardless of software load.

3. Hardware Carbon vs Grid Coupling

Carbon emissions are directly proportional to electricity consumption modulated by regional grid carbon intensity ($I$). Running high-intensity workloads during low-carbon grid hours or in renewable-dominant cloud regions can yield up to a 70% emissions reduction without code modifications.

4. Software Efficiency Recommendations

  • Algorithmic Optimization: Replacing $O(n^2)$ search/sort operations with $O(n \log n)$ reduces total active CPU cycles.
  • Event-Driven Duty Cycles: Utilizing asynchronous event loops (e.g. asyncio) rather than busy-waiting polls allows CPU cores to enter deeper C-states (C6/C7).
  • Workload Batching: Concentrating sporadic workloads into bursty batches maximizes the time CPU packages spend in low-power idle states.
